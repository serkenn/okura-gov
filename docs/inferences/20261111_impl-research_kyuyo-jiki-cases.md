# 推測：給与の年分の割当て（所基通36−9）と死亡後の給与の規則を当てた架空の設例と、検証の方法（impl-research kyuyo-jiki）

- 作成日：2026-11-11
- 種別：仮説をもとにした推測。前提の仮説：［H-KJ］`docs/hypotheses/20261111_impl-research_kyuyo-jiki-model.md`（HJ1〜HJ5）、［H-TK］`docs/hypotheses/20261111_impl-research_tsukin-model.md`（HT2）。
- 設例はすべて架空。設例 S1〜S10 の割当ては実測 `docs/measurements/20261111_impl-research_kyuyo-jiki-fetch-and-checks.md` §3.2（`scripts/IMPL2_kyuyo-jiki_checks.py`）で機械的に出したもの。

## IJ1 遅配の給与が年分を動かし、2年分の扶養の判定が変わりうる

- 前提：HJ1・HJ3。
- 設例（S2）：アルバイトの子。規程の支給日 2025-12-25 の 12月分 200,000円が、支払者の都合で 2026-01-05 に支払われた。
- 推測：
  - 36−9 の読みでは 2025年分の収入。今の判定コア（支払日の年）は 2026年分に入れる。
  - 2025年分の給与等の収入金額が境目（令和7年分の扶養親族の所得要件を給与収入で表した 123万円以下：`docs/public-sources/20261109_impl-prep_kyuyo-sources.md` §4.4）の近くにあると、どちらの年分に入れるかで2年分の扶養の判定が両方とも変わりうる。
  - 源泉徴収票（2025年分）の「支払金額」には、この 200,000円が未払として内書きされているはず（手引の書き方）。判定コアの年分と源泉徴収票の区切りが一致する。
- 検証の方法：単体テスト（`due_on` 2025-12-25・`paid_on` 2026-01-05 → 2025年分）。源泉徴収票の記載（架空）との照合：判定コアの「支払者ごと・年分ごとの給与等の総額」が源泉徴収票の「支払金額」と一致すること。

## IJ2 未払の給与

- 前提：HJ2（未払も記録にする）。
- 設例（S3）：支給日 2026-12-25 の給与が、2027年3月の申告の時点でも未払。
- 推測：36−9 の読みでは 2026年分の収入に入る。今の中間表現には支払日のない給与の記録がなく、数えられない。案A（`due_on` 必須）でも、未払の記録を書く口がなければ同じ。未払の記録を許すと、源泉徴収税額は 0（支払っていないので徴収されていない）として扱うことになるが、確定申告で差し引く源泉徴収税額の定義（UJ4）は確かめていない。
- 検証の方法：単体テスト（未払の記録が支給日の年分の収入金額に入ること）。UJ4 は一次情報（所法120 ほか）を取得してから期待値を決める。

## IJ3 死亡した受給者

- 前提：HJ4。
- 設例：受給者が 2026-03-15 に死亡。
  - S7：支給日 2026-03-25 の給与を遺族に支払 → 所得税の計算に入れない（9−17、質疑応答事例 7/05 と同じ日付の形）。根拠「通達＋国税庁の説明」。
  - S9：支給日 2026-02-25 の給与が死亡時に未払で、2026-03-25 に遺族に支払 → 被相続人の 2026年分（準確定申告）の収入に入れる。今の判定コアは「死亡の日以後の支払」として対象外にしている。
  - S10：支給日が死亡の日と同じ 2026-03-15 → 入れる場合と入れない場合の両方で評価し、合計所得金額などの判定が分かれれば未確定（UJ2）。
  - S8：S7 で「相続税の課税価格計算の基礎に算入されるか」の入力がない → HJ4 では国税庁の説明どおり入れないと計算する（実測の S8 は関数の作りとして「未確定」を出しているが、HJ4 の採用後は S7 と同じになる）。
- 推測：死亡の判定を支払日から支給日に替えると、S9 のような「死亡前に支給期が来ていた未払の給与」が対象外でなくなり、準確定申告の給与等の収入金額に入る。
- 検証の方法：単体テスト（質疑応答事例 7/05 の日付：3/15 死亡・支給日 3/25 → 入れない。支給日 2/25 → 入れる）。

## IJ4 通勤手当の版の選択と同じ日

- 前提：HJ5、HT2。
- 設例：規程が「当月分を翌月10日支給」。2026年3月分の通勤手当の受けるべき日は 2026-04-10。
- 推測：年分は 2026年分（36−9）、通勤手当の限度額は R8 の表（令和8年4月1日以後に受けるべき）。同じ `due_on` で年分と版の両方が決まる。今の判定コアは `when.on`（支払日）しか持たないので、支払が遅れると版と年分の両方がずれうる。
- 検証の方法：単体テスト（2026-03-31 と 2026-04-01 の境目、差額の追給の元の日）。

## IJ5 判定コア・中間表現の変更点の見込み

- 前提：HJ1〜HJ5。
- 推測：
  1. 中間表現：`salary_payment` に `due_on`（または「定めなし」）、`paid_on`（空を許す）、`kind`（差額・役員賞与など）、差額の元の日・改訂の効力の日を足す。`when.on` の意味を決め直す（支払日のままにするか、支給日にするか）。
  2. 判定コア：年分の割当てを 36−9 の日で行う関数を足し、根拠を「通達（所基通36−9）」に替える。死亡の判定を支給日で行い、9−17 に当たるものは値 0（根拠つき）にする。
  3. `due_on` の未入力の扱い（UJ1 の案A〜C）はユーザーの判断を待つ。
- 検証の方法：上の単体テスト。既存のテスト（支払日で年分を決めるもの）は、`due_on`＝`paid_on` の入力で同じ結果になることを確かめる（後方互換の性質のテスト）。
