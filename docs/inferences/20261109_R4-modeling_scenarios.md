## 0. 検証の共通手順

1. **環境**：R2 の実測と同じ手順で、隔離した venv に `openfisca-core==46.0.1` を wheel だけで入れる（[OF-run] の「再実行の方法」）。Windows では `python -I -X utf8` で実行する（[OF-run] T00。UTF-8 モードなしでは日本語の YAML を読めない）。版を固定する（[H-R2] H2）。
2. **実測スクリプト**（未作成。このタスクでは書かない）：`scripts/R4_entity_model_check.py` を作り、R2 の `scripts/R2_openfisca_check.py` と同じく、一時ディレクトリに試験用の国パッケージを書き出して YAML テストを実行する。結果は `scripts/results/R4_entity_model_check/` に置き、`docs/measurements/<実施日>_R4-modeling_entity-model-check.md` に記録する。
3. **試験用の国パッケージの中身**（最小限）：
   - エンティティ：Person、扶養所属（申告者 `max: 1` を最初、扶養親族等）、法律婚（配偶者 `max: 2`）、健康保険（対象外を最初、被保険者 `max: 1`、被扶養者）（[H] H1.1〜H1.3、H1.6）。
   - パラメータ（**ダミーではなく docs の値**。日付は [H-R1] H2 に従って年分の1月1日）：扶養親族の所得要件 2025-01-01: 580000、2026-01-01: 620000（[IT] §2）／扶養控除 380000・特定扶養 630000（[IT] §2）／特定親族特別控除の区分（[IT] §3、[NTA] §2.2 の TA1177 の表）／給与所得控除（令和7年分 収入190万円以下 650000、令和8年分 措法第29条の4第2項の式。[IT] §2）／基礎控除（[IT] §2）／医療費控除の足切り 100000 と 5%（[IT] §4）／健保の収入基準 130万円、19歳以上23歳未満は 2025-10-01 から 150万円（[SH] §1.1・§1.2）。
   - 変数（人）：生年月日、給与の支払額（月）、業務の収入・直接経費・家事関連費と按分率・区分できるか（年）、帳簿の保存（年）、社会通念上の事業か（D4、年）、給与所得、業務の所得と区分、合計所得金額、12月31日の年齢、申告者との続柄、申告者と生計一、配偶者の申告書に記載するか、扶養の区分（なし／一般／特定扶養／特定親族）、控除の対象となる医療費（補填後。状況の組み立てが入れる）、総所得金額等、医療費控除額、健保の今後1年の収入見込み、被保険者との続柄、被保険者と同一世帯か、被保険者からの援助額、被扶養者の目安。
   - 変数（グループ）：扶養所属の扶養控除・特定親族特別控除の合計（申告者へ戻す）、健康保険の被保険者の年間収入。
4. **状況の組み立て**（[H] H2.1・H6 提案2）を Python の関数として作り、中間表現の JSON（手で書いた例）から判定の時点ごとの situation を作る部分を、OpenFisca と切り離して単体テストする。医療費の補填の限度・受診日／支払日の照合もここでテストする（[H] H3.3 案A）。
5. **YAML テストは手で書く**。パラメータ・テストの YAML はコードと同じ扱いで、外部から自動生成しない（[H-R2] H2。[OF-run] T10 で任意の Python 呼び出しができた）。
6. **期待値**は下の各推測に書いた public-sources の節から手で計算したもの。テストの YAML のコメントに計算の途中と出典の節を書く。
7. **令和7年分**（S2・S3）は、ユーザー本人が作成コーナーに架空の数字を入れて得た申告書の欄の金額とも照合できる（[H-SAK] H2。二次的な照合。正解の根拠は法令・通達の一次情報）。令和8年分は作成コーナーで令和8年分が公開されるまで照合できない。
8. 期待値と結果が食い違ったら、(a) モデル（エンティティ・状況の組み立て）、(b) パラメータ、(c) 期待値の読み違い、のどれかを public-sources の原文に戻って確かめ、measurements に記録する。

## S1 別居して仕送りを受ける大学生（令和8年分）

### 前提

- [H] H1.1（扶養所属。特定扶養親族か特定親族かはコアが決める）、H1.3（健康保険。最初の役割は対象外）、H1.4（住民票の世帯はグループにしない）、H2.1（所得税は12月31日、健保は判定日で切り出す）、H4（生計一は D4）、H6（状況の組み立てはコア）。
- [H-R1] H1・[H-SAK] H3（年齢は12月31日の現況、誕生日の前日に加算）、[H-R3] H1（記録の事実の粒度）。

### 入力（中間表現の要点）

| 項目 | 値 |
|---|---|
| 人 | 父（会社員、健保の被保険者）、母（会社員、健保の被保険者）、子（2006-05-10 生まれ） |
| 子の給与の支払（雇用契約、支払者1社） | 2026年1〜12月の合計 1,400,000円（月ごとに入力。例：116,000円×10か月＋120,000円×2か月） |
| 子の他の収入 | なし |
| 送金 | 父 → 子、毎月、名目「生活費・学資金」（変種で月120,000円／月80,000円） |

### 推測（期待値）

| 出力 | 期待値 | 計算 | 出典 |
|---|---|---|---|
| 子の12月31日の年齢 | 20 | 2006-05-10 生まれ | [CON] §2.2、§5.1（所法85③） |
| 子の給与所得 | 660,000円 | 措法第29条の4第2項：74万1千円以上219万1千円未満は「収入−74万円」→ 1,400,000 − 740,000 | [IT] §2 の表の下の注記 |

### 検証方法

- §0 のパッケージで、YAML テストを2本書く：(1) `period: 2026` の所得税（扶養所属：父のインスタンスに子）、(2) `period: year:2026-04-01` の健保（健康保険：父のインスタンスに子を被扶養者）。(2) を仕送りの額だけ変えて2通り。
- 状況の組み立ての単体テスト：中間表現の区間（生計一、健保の認定）から、2026-12-31 と 2026-04-01 の2つの situation が作られ、住民票の世帯が所得税の判定に使われないことを確かめる。
- 反証になる結果：父の控除が 63万円以外、または健保の目安が仕送りの額で変わらない。
- 追加の推測（後回し）：同じ子の令和9年度の住民税では、前年の合計所得66万円（自治体の資料では令和9・10年度の給与所得控除の最低額74万円）で特定親族になり、前年の合計所得95万円以下なので控除は45万円になるはず（[LT] §2・§3、[SH] §4）。ただし、地方税法第314条の2第1項第12号が令和9年度にも同じ文言であることは [LT] §4 の差分の範囲からの推論で、住民税の扶養の所属の規則は未決（[H] U6）。

## S2 同居の高校生のイラストの業務委託収入と家事按分（令和7年分）

### 前提

- [H] H4（按分率と区分できるかは D4、社会通念上の事業かは D4、所得区分そのものはコア）、H5.3（家事関連費は費目別の支出額と D4 の按分率・区分できるかを中間表現に入れる）。
- [H-R3] H1（事業所得か雑所得かの材料、家事関連費の材料）。

### 入力

| 項目 | 値 |
|---|---|
| 子 | 2008-05-01 生まれ（2025-12-31 に17歳）、高校生、父母と同居 |
| 業務委託の報酬（イラスト、業務委託契約） | 2025年の合計 800,000円 |
| 業務の直接の支出（画材・ソフト。D4 で業務関連と判断） | 200,000円 |
| 家事関連費：通信費 | 120,000円。D4：業務の割合 40%、明らかに区分できる（根拠：利用時間の記録） |
| 帳簿の保存 | あり（記録そのものが帳簿）。D4：社会通念上事業と称するに至る程度ではない |
| D4 | 子と父は生計を一にする（同居。所基通2-47（2））。子を父の扶養親族等として記載する |

### 推測（期待値）

| 出力 | 期待値 | 計算 | 出典 |
|---|---|---|---|
| 必要経費に入る通信費 | 48,000円 | 明らかに区分できる部分だけ：120,000 × 40% | [NTA] §1.3（45-2、TA2210） |
| 子の業務の所得の区分 | 業務に係る雑所得 | 帳簿の保存あり → 注の前段（社会通念）で判定し、D4 が「事業ではない」 | [NTA] §1.4（35-2） |
| 子の合計所得金額 | 552,000円 | 800,000 − (200,000 + 48,000) | [IT] §4（所法35：総収入金額−必要経費） |
| 子は父の控除対象扶養親族か | 該当する（一般） | 令和7年分 58万円以下、16歳以上、19歳未満 | [IT] §2、[CON] §3.3 |
| 父の扶養控除 | 380,000円 | 控除対象扶養親族38万円 | [IT] §2 |
| 変種A：D4 を「明らかに区分できない」に変える | 父の扶養控除 0円 | 通信費は必要経費に入らない → 合計所得600,000円 > 580,000円。17歳なので特定親族にも当たらない | [NTA] §1.3、[IT] §2、§3 |
| 変種B：D4 を「事業と称するに至る」に変える | 区分は事業所得、合計所得金額は552,000円のまま、父の扶養控除は380,000円のまま | 事業所得も総収入金額−必要経費（青色申告特別控除などは扱わない） | [IT] §4（所法27・35） |
| 変種C：帳簿の保存なし | 区分は業務に係る雑所得（D4 によらない）、合計所得金額は同じ | 帳簿書類の保存がなく、収入金額300万円以下 | [NTA] §1.4（35-2 注の後段） |
| 子自身の所得税の課税所得 | 0円 | 令和7年分の基礎控除は合計所得132万円以下で95万円 | [IT] §2 |

- 注意：通達 45-2・TA2210 が業務に係る雑所得の計算にも当てはまる前提で書いた。所法45・所令96 の原文は docs にない（[H] U10）。

### 検証方法

- §0 のパッケージで `period: 2025` の YAML テストを、基本＋変種A〜Cの4本書く。D4 の値は人の変数の入力として与える。
- 確かめること：(1) 按分の当てはめ（45-2）がコアの式にあり、中間表現は支出額・按分率・区分できるかの3つだけを渡していること、(2) 所得区分を変えても合計所得金額が変わらないこと、(3) 境目（58万円）の前後で扶養控除が 38万円 ↔ 0円 になること。
- 二次的な照合：ユーザーが作成コーナーの令和7年分で、父の申告書に子（17歳、雑所得 552,000円／600,000円）を入れ、扶養控除の欄を記録する（[H-SAK] H2）。
- 反証になる結果：変種Aで 0円にならない、変種Bで合計所得金額が変わる。

### 検証方法

- 状況の組み立ての単体テスト（OpenFisca なし）：中間表現の明細と D4 の区間から、支払者ごとの「控除の対象となる医療費（補填後）」が父 240,000円・母 90,000円・子 0円・祖母 0円になること、変種で父 180,000円になること。

- 出力の整形との照合：記録の明細から作った医療費控除の明細書の合計（補填を除く前と後）と、コアの値が一致すること（[H] H3.3）。
- 二次的な照合：ユーザーが作成コーナーの令和7年分で、父の医療費（P1〜P3 と補填）を入力し、医療費控除の欄が 140,000円になるかを見る（[H-SAK] H2）。

## S7 グループに書き忘れた人（T04 の影響）

### 前提

- [H] H1.6（最初の役割を「申告者」「配偶者」「対象外」にする）。

### 推測

- 祖母を健康保険のグループに書き忘れると、祖母だけのインスタンスの「対象外」になり、父の健保の被扶養者の数・被保険者の年間収入の計算は変わらない。被保険者として扱われることはない（R2 の T04 では最初の役割が「被保険者」だったために被保険者になった）。

- したがって、書き忘れは「誤って控除や被扶養者が増える」形では起きず、「付け忘れ」の形でだけ起きる。付け忘れは中間表現の検査（全員の所属を必須にする）で止める。

### 検証方法

- 同じ家族で「全員を明示した入力」と「祖母・子を書き忘れた入力」を OpenFisca に直接渡し（検査を外す）、[OF-run] T04 と同じ方法で自動で作られたインスタンスの役割を確かめる。
- 中間表現の検査の単体テストで、書き忘れが拒否されることを確かめる。
