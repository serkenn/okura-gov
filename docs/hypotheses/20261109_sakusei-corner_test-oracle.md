# 作成コーナーの計算結果を、判定ロジックのテストの照合先に使えるか

- 作成日：2026-11-09
- 作業の群（title1）：`sakusei-corner`
- 種類：仮説（hypotheses）
- 根拠にした実測：`docs/measurements/20261109_sakusei-corner_client-analysis.md`（以下「実測」）だけ。

## H1：作成コーナーの静的ファイルから、計算式や基準額を読み取ることはできない

- 内容：作成コーナーの税額・控除額の計算と基準額はサーバー側にあり、ブラウザに届くファイル（フォームを送信せずに取得できるもの）からは、OpenFisca 側の計算式やパラメータの参考になるものは得られない。
- 根拠：実測 §5（基準額の数字が見つからない、共通 JS の関数は表示・入力補助・形式チェックだけ、入力チェックもサーバーへ POST している）、§6.1（依頼した項目はすべて「見つからなかった」）。
- 反証の条件：所得税の入力画面（フォームを送信した先）の画面固有の JS に、基準額や計算式が入っていることが分かった場合。実測 §9 のとおり、その JS は確かめていない。
- 確かめ方：ユーザーが許可した場合に限り、所得税の入力画面へ進んだときにブラウザが読み込む JS の URL と中身を調べる（実測 §10 の「入力画面へ進む方法がない」）。

## H2：作成コーナーで人が作った申告書の数字は、テストの照合先（二次的な確認）に使える

- 内容：ユーザー本人が、作成コーナーを通常の利用のしかた（提出方法で「書面」を選び、e-Tax に送信しない）で使い、架空の家族の数字を入力して得た計算結果（印刷用の申告書の金額）は、OpenFisca のテストケースの期待値を確かめる材料になる。
- 根拠：実測 §5 の結論（計算はサーバー側で行われ、国税庁の実装が出す結果になる）、§4（令和7年分が開いている）、§7（年分ごとに別のアプリ）。
- 条件・限界：
  - 作成コーナーの結果は法令そのものではない。期待値の**正解の根拠は法令の一次情報**（R1 の整理）にし、作成コーナーの結果は食い違いを見つけるための二次的な照合に使う。食い違ったときは、どちらが正しいかを法令で判断する。
  - 照合できる年分は、作成コーナーが開いている年分（実測 §4：2026-11-09 時点で令和3年分〜令和7年分）だけ。令和8年分は、作成コーナーで令和8年分が公開されるまで照合できない。
  - 入力はフォームの送信を伴う。この調査の担当者（エージェント）は、フォームの送信をしない条件で作業しているので、行うのはユーザー本人になる。入力したデータはサーバーに送られる（実測 §5 の 4・5）ので、実在の人の情報ではなく架空の数字を使う。
  - 作成コーナーの利用規約の禁止行為（実測 §0.1）に、税理士等以外の者が他人の確定申告書の作成などを業として行うことについての一文がある。架空の数字で自分の操作として試すことがこれに当たらないかは、この仮説では判断していない（ユーザーの確認が必要）。
  - 作成コーナーの画面は、扶養親族の所得要件などを「判定結果」としてではなく、申告書の欄の金額として出すと考えられる（I）。判定ロジックの中間の値（たとえば特定親族に当たるかどうか）の照合には、申告書の欄に出る値から逆に確かめる工夫が要る。
- 確かめ方：ユーザーが作成コーナーで、給与収入だけの子供がいる架空の世帯（たとえば子の給与収入が扶養の境目の前後になる2〜3通り）を入力し、印刷用の申告書の扶養控除・特定親族特別控除・基礎控除の欄を記録する。同じ入力を OpenFisca 側のテストケースにして、一致を確かめる。

## H3：年齢の判定の式は、作成コーナーと同じ式を使ってよい

- 内容：扶養親族などの年齢の判定（その年12月31日の現況）は、「対象の年 − 生まれた年（1月1日生まれは +1）」で計算してよい。
- 根拠：実測 §6.2・§8（`jsGetAge` の式が、R1 の整理した年齢計算ニ関スル法律・民法第143条・所得税法第85条第3項と一致した）。
- 限界：年の中途で死亡・出国した場合は、その時の現況で判定するので、この式だけでは足りない（実測 §8）。
