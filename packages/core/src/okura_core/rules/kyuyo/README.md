# rules/kyuyo：給与所得

登録済み（rules/__init__.py）。給与等の収入金額（入力の組み立て：支給日で年分を決める・非課税の通勤手当を除く・源泉徴収票を優先・事業専従者控除額のみなし給与と退職手当等に当たらない給与を足す）と給与所得の金額（未払の給与の回収不能〔所法64①〕・特定支出控除〔所法57の2。2026-11-12〕を含む）・給与所得控除額を計算する。

このディレクトリだけで規則を足す（packages/core/README.md §10「規則モジュールの足し方」）。共有のファイル
（evaluate.py・situation.py・country/__init__.py・concepts/structure.yaml など）は触らない。登録は rules/__init__.py の1行だけ。

## 4. 実装の要点

使う記録：`salary_payment`・`commuting_status`・`withholding_slip`（`slip_type: salary` だけ）・`disability_basis`（障害者の2km未満の自動車通勤の当てはめ）・`specific_expense`（特定支出の候補の支出。2026-11-12：KY-11）。選択：`選択.特定支出控除`（2026-11-12：KY-11）。判断：`判断.通勤の合理的な運賃`・`判断.通勤手当の限度の当て方`（通勤手当の未入力・読みの分かれ目。単調な判断の両端評価）・`判断.障害者の通勤の特別の事情`（2026-11-12）、`判断.給与の支給期が死亡前か`、`判断.特定支出の通常の範囲の額`（2026-11-12 の2回目：KY-13）。

- **年分（D23 K3・所基通36−9）**：支給日 `attributes.due_on`（必須）の年の支払を数える。支払日 `when.on` では決めない。定めがないときは `due_on` に支給を受けた日を書き `due_stipulated: false`。未払の給与も `unpaid: true` で記録できる（`when.on` には支給日を書く）。認定賞与 `deemed_bonus`（36−9(4)：支給日、定めがなければ現実に支給を受けた日）は同じ `due_on` で数える（根拠 `DEEMED_BONUS_RULE`、法令の読みの印。「その日が明らかでない場合」は語彙がない）。役員の利益連動の賞与 `officer_bonus_by_resolution`（36−9(2)）は決議等の日 `resolution_on`、総額だけの決議で各人ごとの支給金額が後で定められたときはその日 `amount_fixed_on` の年で数える（`inputs.due_date`。死亡の前後〔9−17 の注〕・通勤手当の版も同じ日。根拠 `OFFICER_BONUS_RULE`）。`resolution_on` がなければ入力の不足（KY-01。`due_on` の年分で検出）。
- **所法56 の受取側の給与（2026-11-12）**：生計を一にする親族の事業から受けた給与のうち所法57① の範囲を超える部分を、段 `事業専従者のみなし給与` で income_kinds の値を読んで給与等の収入金額から引く（業務からの給与は所法56 の当てはめの読みで分かれ目）。
- **未払のまま回収できなくなった給与（所法64①・所令180②。KY-08、2026-11-12）**：`salary_payment` の `amounts.uncollectible_amount` の合計を回収不能額等
  （`所得税_回収することができないこととなった給与等の金額`）にする。なかったものとみなす額は、一 回収不能額等が生じた時の直前に確定している総所得金額・退職所得金額の合計額
  （income_totals。損益通算・純損失と雑損失の繰越控除の後：所基通64−3）と、二 G(収入)−G(収入−回収不能額等)（`所得税_回収不能額等に係る給与所得の金額の差額`）のいずれか低い金額
  （docs/public-sources/20261112_impl-research4_shotoku-laws-and-nta.md §1・§1.1・§1.3、仮説 H1、推測 I1）。
  - 当て方の読み（法令の読み・`UNCOLLECTIBLE_RULE`・`uncollectible.CAP_RULE`）：法64① は「当該各種所得の金額の合計額のうち…に対応する部分の金額は、当該各種所得の金額の計算上、
    なかつたものとみなす」なので、なかったものとみなすのは**給与所得の金額**の部分。給与所得の金額から min(一, 二) を引き、**給与等の収入金額は変えない**
    （措法41の3の11① の850万円・申告不要の2,000万円・住民税の窓口などが使う「その年中の給与等の収入金額」は、64① の対象の「各種所得の金額」でない）。
    二が低ければ収入から回収不能額等を除いた給与所得と同じ（I1）、一が低ければその額だけを引く（収入金額をどれだけ減らしたかには読み替えない）。
    以前（2026-11-12 の最初の実装）は給与等の収入金額から除いていた。給与所得の金額は二が低い限り同じで、変わるのは収入金額を使う値だけ。
  - 一号の額は、給与所得を回収不能額等の前の額（`所得税_所得税法第64条第1項を当てる前の給与所得の金額`）にして income_totals が計算し、段階評価の段
    `未払の給与の回収不能`（uncollectible.py）が `所得税_給与の回収不能額等の上限` に写す。公的年金等に係る雑所得も前の額（income_kinds の窓口）。
    段は扶養の判定の段（personal_deductions。判定用の合計所得金額が給与所得の金額を引く）より前なので、所得金額調整控除の第1項の「有するか」を読めない。
    income_totals が「有するか」の偽・真の2つの額を出し、なかったものとみなす額が同じならその額。違えば段が「有するか」を late_reads で読み、共有の段階評価の不動点の繰り返し（registry.StageSpec.late_reads。2026-11-12）で決める（KY-10）。
  - 総所得金額に措置法の読替え（上場株式等の所得を加える）は当てない（docs で見た読替えの対象は所法2①30・71〜87：法令の読み）。山林所得は範囲外（D20）。
  - 申告の後に回収不能となったときの更正の請求（所法152：事実が生じた日の翌日から2月以内）は、判定コアの値ではない（その年分の値を出すだけ）。
- **退職手当等に当たらない給与（IK-25、2026-11-12）**：判断.退職の性質 が `is_retirement_allowance: false`・`income_type: salary` の retirement_payment の総支払額を、
  income_kinds が支払の日（`when.on`）の年分の `所得税_退職手当等に当たらないとした給与等の収入金額` にし、段 `事業専従者のみなし給与` で給与等の収入金額に足す。
  年分は給与の収入すべき時期（所基通36−9(1)）で、retirement_payment に支給日の定めの欄がないので支払の日を「支給を受けた日」と読む（退職の日〔36−10〕では決めない）。
  源泉徴収税額は tax が retirement_payment の `withholding_tax` を支払の日の年分で数える（tax のファイルは変えない。影響は §5）。
- **事業専従者控除額のみなし給与（所法57④）**：白色の事業主の事業専従者控除額（income_kinds）を、専従者の給与等の収入金額に足す（段 `事業専従者のみなし給与`。根拠 `DEEMED_RULE`）。事業主の事業専従者控除額が対象外なら、income_kinds がみなし給与を対象外にし、段の `uses` で給与等の収入金額へ伝わる。
- **死亡後の給与（所基通9−17、D22 S10）**：支給日が死亡の日より後なら入れない（値 0・根拠つき。相続税の課税価格の確認は要しない読み：国税庁の質疑応答事例 7/05・7/16）。死亡の日と同じ支給日・定めのない給与の死亡後の支払は `判断.給与の支給期が死亡前か` の分かれ目（金額が分かれれば未確定）。
- **通勤手当の非課税（tsukin.py、所法9①五・所令20の2）**：給与等の収入金額＝総支給額（`gross`。`commuting_allowance` は内数）＋現物の定期券の価額（`commuting_pass_value`。外数）−非課税の額。限度額の版は支給日（差額の追給 `retroactive_difference` は `original_due_on`）で選ぶ（年分では選ばない。パラメータ `所得税.通勤手当の非課税限度額.版`）。単位は受給者×支払者×月（質疑03-21）。
  - 交通手段の事実 `commuting_status`（交通機関／交通用具／併用、片道の距離、駐車場等）と合理的な運賃の判断があれば確定。ない部分は0〜限度額の幅（両端評価。tsukin HT5）。
  - 明細の `commuting_nontaxable_stated`（支払者が付けた区分）は、通勤の状況・判断で決まらないときに使う。`commuting_itemized: false` は全額課税（質疑03-22）。
  - 読みの分かれるところ（UT1 複数月・UT2 2以上の支払者・UT3 支給の月）は両端を評価する（`判断.通勤手当の限度の当て方` で決められる）。
  - 同じ支払者の同じ月に交通手段の違う通勤の状況（一次情報なし：質疑03-20 は距離の変更だけ）は、それぞれの交通手段の号の限度額の全部を候補にし、下端の最小〜上端の最大を同じ読みの分かれ目の両端で評価する（`tsukin.mixed_limit`、根拠 `MIXED_MEANS_RULE`。D21 R6・D22 S1）。
  - 障害者（その月に `disability_basis` がある人）の片道2km未満の自動車通勤：質疑03-18 は合理的な運賃の額を限度額として「差し支えない」とする。`判断.障害者の通勤の特別の事情`（2026-11-12 に語彙を足した。人・支払者・期間）が真なら合理的な運賃の額（未入力なら判断の分かれ目）、偽なら全額課税（根拠 `DISABLED_SPECIAL_RULE`）。未入力・食い違いなら 0（全額課税）〜合理的な運賃の額（未入力なら交通機関等の上限）を `判断.通勤手当の限度の当て方` の両端で評価する（`monthly_limit(disabled=True, special=None)`、根拠 `DISABLED_SHORT_RULE`）。
  - この2つは、明細の `commuting_nontaxable_stated` があればそれを使う（支払者の区分）。

## 6. 足し方の手順（要約）

1. 一次情報（docs/public-sources・docs/measurements）で条文・基準額・施行日を確かめる。記憶で値を書かない。
2. parameters/ に YAML（日付のキーは適用開始日、metadata に law・source_kind・reference・施行日）。表は data/（SOURCES.json に SHA-256）。
3. 変数（OpenFisca の Variable）を書く。変数名は concepts.yaml の約束どおり。式は同じ層か下の層の変数だけを引く。
4. `__init__.py` の MODULE（registry.RuleModule）に、変数・使う記録の種類・build_inputs・decisions・roundings・groups・checks・rules・basis を書く。
5. concepts.yaml の概念を `実装済み: true` にし、`未実装のとき` を消す。依存する概念・パラメータ・人／年をまたぐ依存・集約点を通らない依存を宣言する。
6. rules/__init__.py に1行を足す（未登録のとき）。
7. このディレクトリの外にテストを置くときは packages/core/tests/test_<名前>*.py。`tests/test_architecture*.py` を通す。
