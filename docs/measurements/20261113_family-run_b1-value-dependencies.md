- 前の記録：`docs/measurements/20261113_family-run_findings.md` の B1（実際の家庭の形で見つけた。そこでは未修正）。

入力の家庭：5人（父・母・子1・子2・子3）が4つの架空の市町村（990011〜990014）に住む。問いは 所得税 令和8年分と 住民税 令和9年度。

- 母：給与所得が、均等割の非課税の基準（級地で変わる）の近く。
- 子1：賦課期日（2027-01-01）に18歳になる（135万円の非課税の判定の時点で、未成年者かが変わる）。
- 子3：所得がなく、父の扶養親族（扶養の所属の選択あり）。母と同じ市町村に住む。
- 市町村の注入データ（級地・135万円の非課税の判定の時点・税率）は、最初の評価では渡さない。

## 2. 直す前の結果（コミット ae16baf のコード。注入データなし）

| 制度 | 値の数 | 決まった | 未確定 | うち、候補の組合せが上限を超えて評価しなかった |
|---|---|---|---|---|
| 所得税 | 620 | 396 | 224 | 224 |
| 住民税 | 240 | 41 | 199 | 199 |

- 所得税の値（ひとり親に当たるか・同一生計配偶者に当たるか・基準所得税額など）が、住民税の注入点（135万円の非課税の判定の時点・級地）の分かれ目に依存した。
- 住民税の未確定の値が依存する市町村の数：3つが18件、4つが181件（自分の住所の市町村だけに依存する値が1件もない）。

## 3. 原因（計測で確かめた経路。計測のスクリプトは使い捨てで、家族のデータを使ったので残していない）

大まかな（安全側の）依存の付け方が、3か所で重なっていた。

| # | 場所 | 以前の付け方 | 何が起きたか |
|---|---|---|---|
| 1 | `evaluate._assemble`（値を集める所・`var_input_bits`） | 人をまたぐ値（ひとり親・扶養親族など）には、**全部の種類のグループ** の組み立て（由来・依存する入力）を付けた（「どのグループを通ったかはトレースに残らない」ため） | 所得税の値が、住民税の扶養の割当てのグループ（住民税の段の値で組む）を通して、住民税の入力と注入点に依存した。計算の後の検出（`check_personal`）が読む値も同じで、その検出が対象外にしうる変数（`所得税_年齢` など。合計所得金額の入力でもある）に住民税の分かれ目が付いた |
| 2 | 同じ所 | 人をまたぐ値は、トレースで通った変数の **全部** を、つながった人の **全部** について依存に数えた | 本人についてだけ読む入力（本人の住所の市町村の級地で決まる非課税の基本額など）が、家族の全員の分で数えられ、ほかの人の市町村の分かれ目に依存した |
| 3 | `evaluate._exact_deps`（作り手の出力ごとの依存） | `build_inputs` が読んだ分かれ目の直積が 1,024 を超えると、出力を書いた時点までに読んだ分かれ目の全部（人に結びつかない分かれ目は全員）に依存させた。市町村の注入点には関係する人の宣言がなかった | 4つの市町村（級地3通り×判定の時点2通り＝6通りずつ）で直積が 1,296 になり、全員の住民税の入力（市町村の注入データと関係のない繰越控除の記録なども）が、全部の市町村の候補に依存した |

## 4. 直したこと

| # | 直し | 場所 |
|---|---|---|
| 1 | 値に由来を付けるグループを、値の概念が宣言した依存をたどって届くグループだけにした（人をまたぐ値でも）。人をまたぐのに宣言したグループが1つもない値だけ、前と同じ全部 | `evaluate.attached_groups` |
| 2 | トレースの閉包に「人をまたぐ辺を通った先で引いた変数」を持たせ、それ以外の変数は値の人についてだけ数える（入力・途中の変数・出力の依存・対象外の理由） | `evaluate._Closure.crossed`・`readers`、`_closure` |
| 3a | 市町村・道府県の注入データの1か所に、その団体の注入データを引く人を宣言した | `rules/juminzei/inputs.place_persons`・`municipal_slots` |
| 3b | `build_inputs` の直積が上限を超えたら、人ごとに、その人に関係する分かれ目だけの直積の全部の組で作り手を呼んで、出力ごとに正確に決める（合計も上限を超えたら前と同じ安全側） | `evaluate._producer_dependencies_by_person` |
| 4 | 1・2 が拠る前提（人をまたぐ読み方は式の AST で読めて、宣言がある）を、構造の検査で厳しくした：エンティティの属性を通した読み方は `<グループ>` で始める。グループの集約の引数に、引数の外でエンティティから引いた値を渡さない | `packages/core/tests/test_architecture.py` の `_FormulaReader` |

ユニットテスト：`packages/core/tests/test_value_dependencies_persons.py`（`attached_groups`、`_closure` の `crossed`、`_producer_dependencies_by_person`、`place_persons`・`municipal_slots`）。

## 5. 直した後の結果

### 5.1 注入データなし

| 制度 | 値の数 | 決まった | 未確定 | うち、上限を超えて評価しなかった |
|---|---|---|---|---|
| 所得税 | 620 | 620 | 0 | 0 |
| 住民税 | 240 | 191 | 49 | 0 |

- 住民税の未確定の値（49件）は、どれも1つの市町村（自分の住所の市町村）の分かれ目だけに依存する。
- 住民税で決まった値が 41 件から 191 件に増えた（級地・判定の時点のどの候補でも同じ値になるもの。例：所得が非課税の基準よりずっと少ない人・多い人の非課税の判定）。

### 5.2 依存を少なく数えていないかの確かめ（注入データ 26 組）

注入データ（級地・判定の時点）を渡して評価した結果と、注入データなしの結果を比べた。組は、基準の組（全部の市町村が最初の候補）、
1つの市町村だけを変えた 20 組（4市町村 ×〔6通り − 1〕）、全部の市町村を同時に変えた 5 組。

| 確かめること | 結果 |
|---|---|
| A. 所得税の値に、住民税の注入点の分かれ目がない | 問題 0 件 |
| B. 注入データなしで決まった値は、注入データのどの組でも同じ値になる | 問題 0 件（決まった値 811 件 × 26 組） |
| C. 未確定の値の、注入データの組に合う候補ごとの値と、注入データを渡した結果の値が同じ | 問題 0 件 |
| D. 1つの市町村の注入データだけを変えて値が変わった値は、その市町村の分かれ目に依存している | 問題 0 件（変わった値は延べ 32 件） |

## 6. 限界

- B〜D は、この家庭と 26 組の中での確かめ。級地・判定の時点の全部の組合せ（1,296 組）は評価していない。
- 税率（均等割・所得割）は候補を持たない注入点なので、渡していない（税額の値は、自分の市町村・道府県の税率の未注入で未確定のまま）。
- つながった人の集まり（どの種類のグループでもつながった人の全部）は前のまま。人をまたぐ辺を通った先で引いた変数は、つながった人の全部について数える（安全側）。
- 段の関数の出力は、前のまま、段が読んだ全部の分かれ目に依存させている（安全側）。
- 2・3b は、人ごとの宣言（`Slot.persons`）と、構造の検査が保証する宣言（人をまたぐ依存・グループの概念への依存）に拠る。宣言が実際と違うときは、
  評価した組の中の確かめ（1つの分かれ目だけが違う2つの組で変わった入力を、その分かれ目に結びつける）でしか見つからない。
