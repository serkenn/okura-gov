## 1. 方法と安全の扱い

- 取得したものは、取得ごとに新しい空のディレクトリに置いた：`.work/downloads/20261111-023324_R3X_kyosai-b_verify/`、`.work/downloads/20261111-024026_R3X_kyosai-b_verify_cmap/`、`.work/downloads/20261111-025144_R3X_kyosai-b_verify_extra/`、`.work/downloads/20261111-025317_R3X_kyosai-b_verify_extra/`、`.work/downloads/20261111-025811_R3X_kyosai-b_verify_extra/`。中で何も実行していない。スクリプトはリポジトリのルートで動かし、パスを渡して読むだけ。リクエストの間は 1.5 秒、User-Agent は `okura-gov-research/0.1`。官報は取得していない。個人の情報は送っていない。
- PDF の文字の取り出し：担当の `scripts/R3X_kyosai-b_pdftext.py` の低い層（RC4・AESV2・AESV3 の復号、オブジェクトの読み出し、/ToUnicode）を写した（import はしない）。文字列の並べ方は担当と変え、**内容ストリームに現れた順のまま**つないだ（担当は y・x で並べ替え）。低い層は同じコードなので独立ではない。独立性は次の3つで補った。
  1. 取り直したファイルの SHA-256 が担当の取得と一致するか（V1）。
  2. 主要な頁を Claude Code の Read ツールで描画して目で読んだ（財務省の運用方針 1〜3頁・55頁、総行福第210号の写し 1〜4頁、公立学校共済組合東京支部の通知 1〜2頁、地方職員共済組合のチラシ、私学共済事業の法令集「その他」20頁、運用方針（抄）1頁）。Read ツールはファイルを実行しない。
  3. 文の比較は自分で書いた正規化（NFKC・空白の除去・漢数字の金額などの置換）で行った（V3・V7）。
- AES は FIPS-197 の試験ベクタ（C.1 AES-128、C.3 AES-256）で自己検査し、どちらも一致した（`checks.json` の `aes_selftest`）。
- 運用方針（抄）（SIGI）の PDF は、縦書きの CID フォント（Adobe-Japan1、Identity-V）に /ToUnicode がなく、担当の取り出しでも文字にならず、Read ツールの描画でも字形が描かれなかった（罫線と頁番号だけ）。そこで、Adobe の CMap 資源 `UniJIS-UTF16-H`・`UniJIS-UTF16-V`（adobe-type-tools/cmap-resources の Adobe-Japan1-7。PostScript の CMap 形式のテキスト。SHA-256 は `fetch_cmap_20261111-024026.json`）を**データとして**取得し、正規表現で読んで CID → Unicode の逆引きを作り、文字にした。コードは実行していない（ライブラリ・ツールとしては使っていない）。逆引きの一部は康熙部首の字（例：U+2F64）になるが、NFKC で通常の漢字になる。
- 縦書きの新旧対照表（総行福第210号の写しの3頁）は、演算子ごとの位置（Tm）で列に分け、本文のフォントの字だけを使い、列を右から左・列の中を上から下に並べ、y = 425 で上の欄（改正後）と下の欄（改正前）に分けた（V7。`soumu_table`）。
- 文書の「」と > の引用（訂正の前 136件、訂正の後 155件）を、取り直した資料のどれかが正規化して含むかを機械的に調べた（V12）。U+FFFD（/ToUnicode に対応のない字形）は任意の1字に一致するとみなし、使った字数を記録した。
