# okura_core.forms：様式の欄の対応表

申告書・明細書・決算書の **欄 → 概念の対応（年分ごとのデータ）** と、判定コアの結果から **欄ごとの値と根拠** を作る純粋関数
（SCOPE §3「様式の欄の対応表」、HANDOFF D19 T5-2）。判定コア（`evaluate`）は様式を知らず、この部品は計算をしない（SCOPE §6-1）。
ファイル（e-Tax の XML・PDF・Excel）を作るのは利用アプリ（SCOPE §4）。

## 1. 使い方

```python
from okura_core.forms import fill_forms

res = fill_forms(scenario.values, "p-1", 2025)   # FormsResult か FormsRefusal（例外は対応表の誤りのときだけ）
if res.ok:
    page = res.form("KOA020-01")                  # 確定申告書 第一表
    f = page.field_at("所得控除/扶養")             # 欄（位置名で引く）。f.code == "G58"、f.number == "㉓"
    f.status, f.value, f.marks, f.conditions, f.value_ids, f.basis
print(res.to_dict())                              # JSON にできる形
```

| 関数・型 | 中身 |
|---|---|
| `fill_forms(values, person, tax_year)` | 結果の値（`result.ResultValue` の並び。ほかの人・時点の値が混ざってよい）から、申告者・年分の欄の値を作る |
| `determine_filing_type(概念→値)` | 申告の型（通常・第三表あり・損失申告。yoshiki-mapping-table H4） |
| `load_year(年分)`・`load_index()` | 対応表のデータ（`YearTables`・`FormTable`・`FieldSpec`）。一覧にない年分は None |
| `check_against_dictionary(表, 概念辞書)` | 対応表の概念 ID の実在と値の型の突き合わせ（テストが使う） |
| `FormsResult` | `filing_type`（型と、決めた値の ID）、`forms`（帳票ごとの `FormOutput`。`use` は True か未確定の None。`rows` は行の区画の割当て）、`not_produced`（作らなかった帳票と理由） |
| `FieldValue` | 帳票・位置名・欄番号・欄コード・行・値の型・**状態**・値・印（見積り・計画）・条件の文・写した結果の値の ID・対応の区分と理由・様式の根拠（`BasisEntry`）・`subject`（行の区画の欄：その行の人）・`unit`（欄の単位） |

| `rows.assign_rows(区画, 行の数, 値, 申告者)` | 繰り返しの行に誰を載せるか（design-output UO23。§4.2）。`RowAssignment`（状態・行ごとの人・あふれ `overflow`・使った値の ID・規則） |

## 2. 状態の扱い（D19・D21 R2）

| 結果の値 | 欄 |
|---|---|
| 予測（D19 の見込み） | その申告者・年分の申告の範囲の値か、欄が使う値に1つでもあれば **全部を出さない**（`FormsRefusal` 予測、止めた値の ID） |
| 見積り（法令が求める見積り） | 出す。`marks` に見積り、`conditions` に「法令が求める見積りによる値（見積り）」 |
| 計画（申告の計画） | 出す。`conditions` に「申告の計画どおりに申告すること（計画）」 |
| 未確定・幅 | 欄の状態は `未確定`、値は幅（`YenRange`）か None のまま。何で決まるかは `value_ids` の値の `undetermined` |
| 対象外 | 欄の状態は `対象外`、理由を写す |
| 結果に値がない | 欄の状態は `値なし`（問いで求めていないなど） |

欄の状態はほかに、`出力`・`空欄`（記入の条件・申告の型）・`対応なし`（区分：事実・判断・対象外・未対応・未決）・`出力しない`（個人番号・還付金の受取口座）。
様式に印字された式（例 ⑩＝⑦＋⑧＋⑨、㉚＝㉖＋㉗＋㉘＋㉙）と単位の印字（0000 など）を、写した値が満たさなければ
その申告者・年分の欄を出さない（`食い違い`。yoshiki-mapping-table H3）。値を出さない欄が混じる式は確かめない。

申告の型：純損失の金額か、その年の雑損失の翌年以後への繰越があれば損失申告、退職所得・上場株式等の分離課税の所得・繰越控除があれば第三表あり、
ほかは通常。前年以前の損失に控除しきれない残りがあるときは、翌年以後に繰り越すか（第四表が要るか）を決める概念がないので未確定にする。
型で空ける欄（損失申告の ⑪・⑫・㉛・62 など）は、型が未確定なら `未確定`。

## 3. データ

## 4. 科目の割当て・行の割当てと、対応する概念がない欄

### 4.1 科目の割当て（design-output UO19。2026-11-12）

- **置き場所**：様式の対応表のデータ `data/r07/割当て/科目.yaml`（年分ごと。版つきの写像ファイルの案：`impl-prep_jigyo-calculation-model` H7）。
  判定コアは様式を知らず（SCOPE §6-1）、必要経費を **内訳のキーごと** に返す（`所得税.<事業所得|不動産所得>の必要経費の内訳.<キー>`、
  `rules/income_kinds/breakdown.py`）。キーは中間表現の閉じた語彙 `business_expense.attributes.expense_category`（`okura_ir.vocabulary.EXPENSE_CATEGORIES`：
  `packages/ir/README.md` §6.2。2026-11-12 に利用者の符号から閉じた語彙にした）と、記録の費目でない内訳（給与の支払・報酬の支払・消費税等・資産の損失）。
- **割当て**：表（一般用／不動産所得用（収支内訳書）／不動産所得用（決算書））ごとに、どのキーもちょうど1つの印字のある科目へ。
  根拠は所規47の3（内訳書の必要経費の区分）と様式の印字、書き方の「必要経費の各科目の具体例」（租税公課に会費・組合費・税込経理の消費税等の納付税額、
  消耗品費にガソリン・少額の備品など）。印字のある科目のどれにも当たらないキーは、様式の「その他の経費」の雑費（不動産所得用の決算書は⑰その他の経費）。
  印字のない空欄の行（利用者が科目名を書く行）は使わない（`空欄`）。

## 5. evaluate への組み込み（申し送り）

**2026-11-12：共有の担当が組み込んだ**（`okura_core/forms_output.py`、core README §3・§4）。問いの任意のキー `forms`（`{"persons": [...]}` か `{"persons": null}`）で、
所得税の年分 × 申告者ごとに `fill_forms` を呼び、`scenarios[].forms` に入れる。欄が読む概念（下の 2・5。`forms_output.form_concepts`：欄・帳票を使う条件・
申告の型・行の割当ての概念）のうち実装済みの人の概念は、出力を持たない途中の概念も年分の全員について結果に出す。施行日前の提出は build_filing と同じ判定
（`result.enforcement_after`）で `RefusalCategory.BEFORE_ENFORCEMENT`（施行日前の提出）として止める（fill.py に区分を1つ足した）。
行の割当てが読む概念は `rows.py` の `C_` で始まる定数から拾う（名前を変えるときは forms_output も直す）。以下は組み込む前の申し送り（記録として残す）。

この部品は `result.ResultValue` を受け取る純粋関数で、`evaluate`・`result.py`・`schema/result.schema.json` は触っていない（持ち場の外）。組み込む担当へ：

1. `evaluate` がシナリオの結果を作った後、問いの所得税の年分 × 申告者ごとに `fill_forms(scenario.values, person, year)` を呼び、
   `ScenarioResult` に `forms`（`FormsResult | FormsRefusal` の並び）を足す。直列化は `to_dict()`。`result.schema.json` に `scenarios[].forms` を足す。
2. 欄が写す値の多くは `出力` を持たない途中の概念（例 `所得税.事業所得の総収入金額`・`所得税.セルフメディケーション税制の選択`）。
   結果には「問いが求めた値と、その depends_on をたどって届く値」だけが出るので、届かない概念の欄は `値なし` になる。
   欄を埋めるには、対応表が使う概念（`FieldSpec.mapping.concepts()` と `determine_filing_type` の概念）を結果に含める必要がある。
3. 申告用の値（`build_filing`）とは別の出力。予測の扱いは同じ（申告者・年分の全部を止める）。施行日前の提出（`filing_date`）の止め方は `build_filing` の側にだけある。
4. 誰を申告者とするか（申告書を出す人）は問いか結果から決める（この部品は渡された人について作る）。
5. （2026-11-12）行の割当て（§4.2）は **ほかの人の値** を読む：配偶者・扶養親族・特定親族・事業専従者の `所得税.扶養親族等とする申告者`・`所得税.扶養親族に当たるか`・
   `所得税.特定親族に当たるか`・`所得税.生年月日`・`所得税.事業専従者の事業主`・`所得税.退職所得の金額` と、行の欄が写す概念（`所得税.扶養等の判定に使う障害者か`・
   `所得税.国外居住親族の区分`・`所得税.特定親族特別控除の1人分の額`・`所得税.事業専従者の専従者給与等の額` など）を、申告者だけでなく家族全員について結果に含める。
   `fill_forms` には年分の全員の値を渡す（今もそう書いてある）。
6. 人の ID の区分の値で「いない」は `"なし"`（`result.Category` は空の文字列を受け付けない）。既存の `所得税.扶養親族等の申告者`（段の入力）は「いない」を空で持つので、
   結果に出すとそのままでは `Category` にできない。行の割当ては空を「なし」にした `所得税.扶養親族等とする申告者`（personal_deductions/filing.py）を読む。
