### 0.2 名前の付け方（案）

| # | 対象 | 案 | 理由 |
|---|---|---|---|
| N1 | 事実の語彙のキー（中間表現の JSON Schema、beancount のメタデータ） | 英小文字の snake_case。日付は `_on`、日時は `_at`、識別子は `_id`、人の参照は役割名（`payer`・`patient`・`recipient` など）。`kind`・`date`・`evidence` のような汎用の語は、beancount のメタデータでは単独で使わず対象を付ける（例：`medical_kind`）(I) | beancount のメタデータのキーは ASCII だけ［BC-run］§2。統合元で `kind`・`evidence` が文書によって別のものを指す［M-VOC］§1 |
| N2 | 法令の概念の ID（概念辞書） | `<制度>.<法令の語>`。制度は 所得税・住民税・森林環境税・国保・国年・健保・共済。必要なときだけ `.<部分>` を1段足す（例：`所得税.事業所得.総収入金額`）(I) | SCOPE §7 の形。統合元の概念 ID らしい名前の多くはこの形［M-VOC］§2。OpenFisca は日本語の名前のまま入出力できた［OFP］§8 |

| N4 | 名前つきの関数（端数・期間・年齢など） | `端数.<制度>.<対象>`、`期間.<名前>`、`年齢.<名前>`。コードの関数名（ASCII）は別名として辞書に持つ。根拠の種類を必ず持つ：D21 R5 の順位（法令＞通達＞手引き＞国税庁の説明。TA・質疑応答事例は国税庁の説明）のどれか、又は順位にないもの（様式の注記・自治体の資料）。根拠がなければ1つの既定を選ばず、**候補の集合**を持ち、候補の全部で評価して分かれれば未確定（D21 R5）。「既定」は金額・判定に効かない表示だけの関数（明細の行の並べ方など）に限る (I)〔独立検証で訂正：作成時は「既定・出典未確認」を出典の種類にしていた。D21 R5 と食い違う。様式の注記を順位のどこに置くかは §5.5 の V-U3。［M-VER］§4〕 | 統合元は ASCII（英語・ローマ字）・日本語・混在の3通り［M-VOC］§3〔独立検証で訂正：作成時は「4通り」。［M-VOC］§3 は英語とローマ字を1つに数える。［M-VER］§2.2〕 |
| N5 | 注入点 | `注入.<種類>.<項目>`（種類は concepts の文書 §4 の表の予定だった。未作成で、注入点の候補は §5.3） (I) | 統合元は「注入データ」「注入するデータ」「保険者データ」などと書き分ける［M-VOC］§4 |
| N6 | 解釈の切替え（一次情報で決まらない読み方） | `解釈.<制度>.<名前>`。採る読み（既定値）と、結果に付ける印を持つ。読みの候補で結論が変わるときは、既定値で断定せず未確定（一次情報）を返す（OUTD §1.2・§5.1 と同じ扱い。〔独立検証で追加〕） (I) | 統合元に `解釈.所法56の対象` などがある［M-VOC］§2 |
| N7 | 問いの欄 | `年分`（所得税）、`年度`（住民税・国保・国年）、`判定日`（健保・共済・第3号）。`認定日` は保険者の決定（事実）、`基準日` は年齢の計算の引数として別に使う (I) | 統合元で 判定日 123・認定日 53・基準日 10 回が混ざる［M-VOC］§4 |

### 0.3 「選択」と「申告書等の記載」の生涯（案）

統合元は「提出前は判断（選択）、提出後は事実」と書く文書と、「記載した（する予定の）事実」と書く文書がある（conflicts の文書 X25。未作成）。次の生涯にそろえる案 (I)。

1. **予定**：判断台帳の「納税者の選択」（判断者・日時・年分・書類の種類）。結果には「選択（未提出）」の印。
2. **提出**：事実台帳の「申告書等の記載」（書類の種類・提出日・提出先・記載した人と区分）。同じ年分の選択は上書きできない。
3. **確定後に変えられないもの**：提出後に修正申告・更正の請求で変えられない選択（課税方式、医療費控除かセルフメディケーション税制か）は、提出の事実があればシナリオで変えたものを拒否するか「提出済みと矛盾」と返す。

- 根拠：申告書等の記載で所属が決まり、記載で変えられる（所令219①）［CON］§4.7、［MISC］§3.2。課税方式の選択は提出後に変えられない［KB］§1.4、§2.2、§5.2。セルフメディケーション税制との選択も同じ［IRN］§6.1。

### 0.4 すべての記録に共通の欄（案）

`record_id`、`recorded_at`（記録した日時）、`evidence`（証憑 ID の並び）、事実の日付（`*_on`）又は区間（`from_on`・`to_on`）、役割ごとの人の参照、`source_kind`（本人の記録／書類の写し／外部で計算した値／保険者・市町村の決定）。D12 の「事実の日付と記録した日時を分ける」に合わせる (I)。根拠：［PS-D］§2.2、§6.1（訂正・削除の記録の要件）、［AO］§1.4（通知の日付で状態が決まる）。
