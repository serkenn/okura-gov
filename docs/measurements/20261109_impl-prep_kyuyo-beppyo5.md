## 1. 方法

1. `/law_data/340AC0000000033?asof=<日付>` の本文 JSON から、`AppdxTable` のうち `AppdxTableTitle` が「別表第五」のものを取り出した。`TableStruct` ごとに、行（`TableRow`）とセル（`TableColumn`）の文字列・`rowspan`・`colspan` をそのまま保存した（`beppyo5_grid_<asof>.json`）。
2. 格子を HTML の表と同じ規則で展開し（rowspan で下の行に伸びるセルは、その下の行の同じ列を占める）、各行の3組（列 0–2、3–5、6–8）を「以上・未満・値」として読んだ。単位「円」の行までを見出しとして飛ばした。値が金額でないセルは「給与等の金額から◯円を控除した金額」（minus）、「給与等の金額に◯％を乗じて算出した金額から◯円を控除した金額」（rate_minus）として定数を取り出した。「◯円未満」（colspan=2）は下限 0 の区分、最後の「20,000,000円」（colspan=2）は1点の値とした。
3. 検査：
   - 区分が隙間なく続くか（前の区分の「未満」＝次の区分の「以上」）。
   - 金額の区分の刻み幅の分布と、刻み幅が続く範囲。
   - 仮説「表の金額 ＝ その版の第28条第3項の式を区分の下限で評価した『下限 − 給与所得控除額』」を全区分で照合。控除額は `Fraction` で正確に計算し、1円未満は切り捨てて比較。
   - 式の区分は、660万円未満はすべての整数で、660万円以上は両端の各2万円と 997 円おきで、第28条第3項の式（1円未満切捨て）と照合。
   - 隣り合う版の表の比較と、1,000円刻みで 0〜6,599,000円の値を比べた「値が違う範囲」。
4. 国税庁が公表した「年末調整等のための給与所得控除後の給与等の金額の表」（令和7年分・令和8年分の PDF）を Read ツールで画像として読み、29 区分を人が書き写して `scripts/IMPL_kyuyo_spotcheck.py` に定数として書いた。各区分の下限・下限+1・中央・上限−1 の4点で、機械抽出の値と比べた。
5. 措置法第29条の4第2項（`IMPL_kyuyo_thresholds.sochi_29_4_2`）と、別表第五（asof 2026-12-01）だけの値を、691,000〜2,199,999円の全整数で比べた。

## 7. 気づいたこと（実装への注意。最後の箇条の「表そのものをデータとして持つほうが確実」は提案で、仮説 H2 として扱う）

- e-Gov の別表第五は、区分を3組横に並べた表で、rowspan（式のセル）と colspan（「◯円未満」「20,000,000円」）を含む。単純に行ごとに読むと区分を取り違える。式の列の上の単位行が空欄の TableStruct がある（令和6年分の（九））。
- 所得税法の別表第五（e-Gov）と国税庁が配る年末調整用の表は、令和8年分では 220万円未満が違う（国税庁の表は措置法を織り込んだもの）。パラメータの出典を「別表第五」とするなら、措置法第29条の4第2項を別に実装する必要がある。
- 表の金額は第28条第3項の式を区分の下限で評価した値と全区分で一致したが、例外が2つある：①「◯円未満 → 0」の区分（式なら最大 999円）、②令和8年分の [2,026,000, 2,028,000) の 2,000円の区分（式の区分の終わりが 2,026,000円で、4,000円刻みの境目に合わせるための区分と見える）。式からの再生成ではなく、表そのものをデータとして持つほうが確実。
