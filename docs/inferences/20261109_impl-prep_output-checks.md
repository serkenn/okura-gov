## I1：令和8年分の第一表・第二表は、令和7年分の新様式から欄が変わる（H4）

- 推測の内容：e-Tax の KOA020（第一表・第二表ほか）が令和9年1月受付でバージョン 24.0 に上がること、施行規則第47条第3項に記載事項が加わる版があること、社会保険料控除等の明細書が新設されることから（H4・H9）、令和8年分の第一表・第二表には、欄の追加（例：第二表の親族欄の列、第一表の区分欄）か欄コードの変更がある。
- 影響：欄値表の対応表（年分×様式ID）を令和8年分用に作り直す必要がある。令和7年分の対応表をそのまま令和8年分に使ってはいけない。
- 補足（2026-11-09 独立検証）：H4 の注記のとおり、施行規則第47条第3項第二十四号（措法第41条の15の5 の扶養親族の氏名・生年月日・続柄・個人番号）は 2026-01-01 施行の版から入っていて、令和8年分・令和9年分の生命保険料控除の特例に関係する。令和8年分の第二表に、この扶養親族を書く欄が加わる候補になる。
- 確かめ方：
  1. 国税庁の様式ページに令和8年分（`/taxes/shiraberu/shinkoku/syotoku/r08.htm` と思われる）が出たら、第一表・第二表の PDF を取得し、令和7年分の欄の一覧（public-sources §2.2・§2.3）と欄ごとに比べる。
  2. 監視（D9）：国税庁「様式変更された申告書等の公表時期・受付開始時期」（ai-ocr.xlsx）に令和8年分の申告書の行が現れるか、e-Tax の帳票一覧と仕様書の更新履歴（2026-11-25 の確定版掲載）を、毎日の確認の対象に入れる。
  3. （ユーザーが CAB の展開方法を承認した場合）e-Tax の「帳票フィールド仕様書【所得税関係】」の確定版で、KOA020 の版 23 系と 24.0 の項目の違いを見る。

## I2：公式の医療費集計フォーム（Ver.3.1）のテンプレートのセルに値を入れただけのファイルは、作成コーナーで読み込める（H3）

- 推測の内容：テンプレートの xlsx（ZIP）のうち、シート1の 9〜1003 行の B〜J 列のセルの値だけを書き換え（共有文字列か inline の文字列、数値）、他の部品（スタイル、入力規則、数式、図、もう1枚のシート）はそのまま残せば、作成コーナーは Excel で保存したファイルと同じように読み込む。新しい xlsx を一から組み立てるより、読み込みに失敗する危険が小さい。
- 反対の可能性：作成コーナーは「推奨環境を満たさない表計算ソフトで作成した医療費集計フォームは読み込みができない場合があります」としている（H3 の限界）。アプリ情報（`docProps/app.xml`）、計算結果のキャッシュ（C3・C4 の値）、共有文字列の数の不一致などで拒まれるかもしれない。
- 確かめ方（ユーザーが行う。エージェントは作成コーナーにフォームを送らない）：
  1. 架空の受診者・支払先で3〜5行（区分の組合せ、補塡あり・なし、全角10文字ちょうど、9桁ちょうどを含む）のファイルを出力層で作る。
  2. ユーザーが作成コーナーで提出方法「書面」を選んで医療費控除の入力に進み、「医療費集計フォームの読込」で読み込む。
  3. 読込結果の「正常件数/読込件数」が行数と一致し、「支払った医療費の合計額」「補てんされる金額の合計額」が出力層の A・B と一致すれば成り立つ。
  4. 失敗したら、同じファイルを Excel で開いて保存し直したものを読み込ませ、差（どの部品が原因か）を調べる。それでも駄目なら、H3 の「合計額 A・B＋明細書を書面で提出」の経路を標準にする。
- 注意：作成コーナーに入れたデータはサーバーに送られる（実在の人の情報は使わない）。

## I3：作成コーナーで「合計額だけ入力」した場合と、明細を読み込んだ場合とで、医療費控除額（第一表㉘）は同じになる（H3）

- 推測の内容：控除額は明細書の A（支払った医療費）・B（補塡される金額）と所得金額の合計額から決まるので、明細の行を入れても合計額だけを入れても、作成コーナーが出す㉘は同じ。
- 確かめ方：I2 と同じ架空のデータで、(a) 集計フォームの読込、(b) 合計額の入力、の2通りを作成コーナーで作り、印刷した第一表の `G62` を比べる。違ったら、作成コーナーが行ごとに補塡の限度を当てているなど、出力層の行の作り方に影響する処理があることになる。

## I4：令和7年分の場面（架空）について、欄値表の値は作成コーナーで作った申告書の同じ欄コードの値と一致する（H1・H2・H5）

- 推測の内容：判定コアが法令どおりなら、欄値表と、作成コーナーで入力値表のとおりに入れて印刷した申告書は、欄コードごとに一致する。
- 確かめ方（D15⑤）：
  1. 場面ごとに入力値表と欄値表を出す。
  2. ユーザーが作成コーナー（令和7年分、書面提出）に入力値表のとおり入力し、印刷用の PDF の第一表・第二表を保存する。
  3. 欄コードごとに値を突き合わせる。食い違ったら法令の一次情報でどちらが正しいかを決める（作成コーナーは正解の根拠ではない）。
- 突き合わせに使う欄（I5 の欄の組）を、場面ごとにテストの期待値にする。

## I6：e-Tax の XML を作らなくても、ユーザーは書面か作成コーナーで申告できる（H1・H2・H8）

- 推測の内容：欄値表で紙の申告書に書く、又は入力値表で作成コーナーに入れて印刷し郵送・持参する、のどちらでも申告は完結する。e-Tax の XML がないことで申告ができなくなることはない。
- 確かめ方：手引きの「申告書の提出方法」（郵便・信書便、税務署の受付）と、作成コーナーの書面提出の流れで、e-Tax を使わない申告の経路が最後まであることを、ユーザーが令和7年分（架空のデータ、送らない）で作成コーナーの印刷まで進んで確かめる。

## I7：令和7年分の新様式（2026-09-24 以降）は、照合（D15⑤）の時に旧様式で作られた資料と食い違って見えることがある（H4）

- 推測の内容：手引き（HTML 版、2025-12-24）と収支内訳書の書き方は旧様式の書き方のままで、新様式の欄コードや区分の記入方法（1・2 などの番号）は「様式変更に伴う記入要領の変更点等」でしか分からない。2026-03 までに作成コーナーで作った令和7年分の申告書（旧様式）と、2026-09-19 以降に作成コーナーで作るもの（新様式）は、見た目と欄コードの有無が違う。
- 確かめ方：照合に使う作成コーナーの印刷結果に様式ID（`NTA1K?A020010230` など。`?` は H4 の注記・H10）が印字されているかを見て、欄値表の様式ID と一致するものだけを突き合わせる。

## I8：令和8年分の第一表・第二表の様式ID は `NTA1KOA020010240`・`NTA0KOA020020240` になる（H10・H4。2026-11-09 独立検証で追加）

- 推測の内容：H10 の構成（`NTA`＋1桁＋e-Tax の様式ID＋ページ＋版4桁）が正しく、e-Tax の KOA020 が令和9年1月受付で 24.0 になるなら、令和8年分の紙の第一表・第二表の様式ID の版の部分は `0240` になる。様式ID が変われば、欄値表の鍵（H4）も変わる。
- 確かめ方：
  1. 令和8年分の第一表・第二表の PDF が公表されたら、様式ID の版の部分が `0240` かを見る（I1 の 1 と同時に行う）。
  2. 英字の O か数字の 0 かは、テキスト層のある資料（e-Tax の「AI-OCR化対象帳票レイアウトの提供について」の資料、作成コーナーが出力する PDF のテキスト層など）で確かめる。どれもテキスト層がなければ「確認できなかった」と記録し、鍵には欄コードと年分・書類名を使う。
- 反証：版の部分が `0240` 以外なら、H10 の「版」の読み方が誤り。
