## 2. 一次情報の取得で分かったこと（`scripts/R3_fetch.py` の各セット）

1. **国税庁はソフト404を返す**：存在しない URL（`/rss/index.htm`、`/rss.xml`、`/law/tsutatsu/kobetsu/shotoku/shinkoku/menu.htm`、`/law/tsutatsu/kaisei/kaisei_a.htm`）に HTTP 200 で、タイトル「指定されたページを表示できませんでした」の同じページ（2,007 バイト、Last-Modified 2024-01-18）を返す。ステータスだけでは削除・移動を検知できない（`nta_index_20261109-132416.json`）。
2. **国税庁の HTML は ETag・Last-Modified があり、条件付き GET で 304 を返す**。ただし TA 8件（1120、1122、1177、1180、1350、1400、1500、2210）の Last-Modified はすべて 2026-09-09 01:00 前後で、本文の表示は「[令和8年4月1日現在法令等]」のまま（`nta_ta_20261109-132708.json`）。所得税基本通達のページも、改正のない項だけのページ（01/07.htm）が 2026-10-02 になっている。
3. 国税庁の文字コードは Shift_JIS と UTF-8 が混在（`charset` を記録）。
4. **通達中の「補塡」は画像**：所得税基本通達 73−8 などでは「塡」を含む語が `<img alt="ほてん" src="/shared/images/unit/hoten.gif">` で表示される。テキストだけを取ると「医療費をする保険金等」のように欠ける。`R3_fetch.py` は alt を `⟨…⟩` で残すように直した。
5. **厚労省の「登載準備中」の PDF は、データベースへの登載後に URL が消える**：検索結果で見つかった `https://www.mhlw.go.jp/hourei/doc/tsuchi/T250724S0010.pdf`、`T251006S0050.pdf`、`T260310S0010.pdf`、`T240112T0010.pdf` は 404（232 バイト）だった（`mhlw_tsuchi_20261109-132940.json`）。同じ通知はデータベースの `t_doc?dataId=...` で取得できた。
6. **厚労省法令等データベースは日付で GET 検索できる**：`/web/t_itemsrch_result?type=1&startGengo=5&yearFrom=7&monthFrom=10&dayFrom=1&endGengo=5&yearTo=7&monthTo=10&dayTo=1&shubetsu=&bango=` で令和7年10月1日付の通知7件の一覧と `t_doc` へのリンクが返る（`mhlw_search_20261109-133111.json`）。`t_doc` の本文ページには Last-Modified がない。昭和52年4月6日（1件）、令和7年7月4日（10件）も同じ方法で見つかった。平成5年3月5日は0件、平成5年3月中は第3号関係の通知が見当たらなかった（`extra_*.json`、`extra2_*.json`）。
7. 総務省の `news.rdf` は `encoding="Shift_JIS"` で、Python の `xml.etree`（expat）は「multi-byte encodings are not supported」で読めない（1回目の probe）。宣言された符号化で文字列にしてから UTF-8 として渡すと読めた（2回目）。
8. **取得が止まることがある**：`feeds_discovery` セットの実行中、国税庁 `users/gensen/index.htm` の取得が5分以上戻らなかった（ソケットの timeout は1回の読み取りごとにしか効かない）。そのため両スクリプトに本文読み取り全体の制限時間（90秒）を入れた。その後の probe では同じ URL を問題なく取得できた。このセットの取得記録 JSON は、途中で止めたため残っていない（その後、記録を1件ごとに書き出すよう直した）。
9. 協会けんぽのトップは Last-Modified・ETag がなく、2回の取得で本文のハッシュが違った（動的な要素がある）。日本年金機構の手続ページ等には Last-Modified があり 304 も返る。
10. RSS の XML は DOCTYPE・ENTITY を含む場合はパースしない（外部実体・実体展開の予防）。今回の3つのフィードには含まれていなかった。

## 3. 再実行で確かめられること

- `python -I scripts/R3_monitor_probe.py` を再実行すれば、§1 の表（ステータス、304 の可否、フィードの項目数、日付）を再取得できる。値は日々変わるが、「どの候補が RSS か」「304 を返すか」「ソフト404 か」は再現するはず（変わっていればそれ自体が仕様変更の検知）。
- `python -I scripts/R3_fetch.py mhlw_search mhlw_tdoc` で、通知の検索と本文の取得を再現できる。
