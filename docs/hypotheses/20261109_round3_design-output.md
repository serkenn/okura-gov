### 1.4 印と状態の伝わり方（案）

1. 印と状態は、**計算の依存**（根拠の木。§2.2）に沿って、依存する値へ伝わる。人をまたぐ依存（扶養される人の所得 → 扶養する人の控除）と年をまたぐ依存（前年の所得、繰越）でも伝わる。
2. **見込み**：見込みの判断に依存する値すべてに付く。その値を写す欄がある申告者・年分の欄値表は出さない。
3. **未確定**：依存する値は、候補ごとに評価して同じ値なら確定、違えば未確定（§5）。
4. **対象外**：依存する値も対象外（由来を根拠に書く）。
5. **出典未確認**：金額には伝える。判定（真偽・区分）は、候補で結論が同じなら伝えない（根拠に「候補を評価した」と残す）。違えば未確定。〔独立検証で訂正：作成時は端数もここに含め「UO6」としていた。根拠のない端数は D21 R5 で §5.1 の手順（候補を全部評価、金額も含めて分かれれば未確定）になった。［M-VER］§4〕
5a. **法令が求める見積り・原文未確認・端数の根拠が法令以外**：依存する値に伝える（欄値表は止めない）。
6. **条件つき**：依存する値に伝わり、条件の文を積み上げる。
7. **食い違い**：伝えない（見つけた所に付ける）。
8. **後の記録に依存**：その年分の値と、それに依存する値に付く。
9. 伝える仕組み：OpenFisca のトレースの木（変数のノードと子）と、状況の組み立てで作る「変数・期間・人 → 事実 ID」の対応で、印の由来をたどる。累進税率表を引いたことはトレースに残らないので、明示して記録する（§2.2）。

## 4. 複数シナリオの一括評価の入出力

### 4.1 入力の形（案）

```json
{"問い": {"所得税の年分": ["…"], "住民税の年度": ["…"], "被扶養者の判定日": ["…"],
          "欄値表": true, "境目の説明": "…"},
 "中間表現": {"…": "共通"},
 "注入データ": [{"…": "共通。出典・取得日・適用期間つき"}],
 "シナリオ": [
   {"ID": "s0", "名前": "判断台帳のまま", "判断の差分": []},
   {"ID": "s1", "名前": "…",
    "判断の差分": [{"判断ID": "j-s1-1", "置き換える判断": "j-…", "種類": "…", "対象": {"人": "…", "年分": "…"},
                   "内容": {"…": "…"}, "判断者": "…", "日時": "…"}]}]}
```

- **共通**：中間表現（事実）・注入データ・法令の版・問い。SCOPE §8「同じ法令の版でまとめて評価する」に合わせる。
- **シナリオごと**：判断台帳への追記の差分（D12 の形。置き換える判断の ID を持つ）。変えられるのは判断台帳の項目（見込み、納税者の選択、申告の計画、所属の選択、計算の既定の切替え）だけにする案。仮の事実や注入データの候補をシナリオで変えるかは未決（UO13）。
- シナリオ `s0`（差分なし）は必ず含める案（比較の基準として。比較そのものはアプリが行う）。

### 4.2 検査（入力の誤りとして止めるもの）

- シナリオの差分が、知らない判断 ID を置き換えている、同じ判断を2回置き換えている。
- 提出済みの年分について、提出後に変えられない選択を変えている（UO17）。
- 差分が事実の語彙（中間表現の項目）を書き換えようとしている（UO13 の案のとき）。
- 誤りのときは、全部のシナリオを評価せず、`{"ok": false, "エラー": [{"場所": …, "内容": …}]}` の形で返す（［OFP］§8 の CLI の形に合わせる）。

## 5. 未確定のときに「何を注入・入力すれば決まるか」を返す形

### 5.1 判断の手順（案）

1. 値を決めるのに足りないもの（未注入の注入点、判断台帳にない判断、事実台帳にない事実、一次情報で決まらない規則、公表前の政令・様式）を「分かれ目」として集める。
2. 分かれ目ごとに候補を作る：注入点のスキーマに列挙した型（公開資料に現れた型）、判断の値の領域、名前つき関数の候補、事実の有無、数値なら下限・上限。
3. 候補を全部評価する。**結論（判定の真偽・区分）が同じなら「確定」**にし、根拠の「候補の評価」に残す。違えば「未確定」にする。
4. 金額の扱い：注入がなくて範囲が有界でない（税率・均等割など）なら値は未確定にし、「式」と決まっている部分を返す。端数は D21 R5 の手順：法令＞通達＞手引き＞国税庁の説明のうち一番強い根拠に従い（法令以外は印「端数の根拠が法令以外」）、根拠がなければ候補の全部で評価して、結論が分かれれば未確定（一次情報）にし、候補ごとの値を返す。判定は同じで金額だけが数円違う場合も「結論が分かれる」に当たるとする読み（作成時の訂正で採った読み）でよいかと、端数でない数え方（期間の数え方など）に同じ手順を当てるかは UO6。〔独立検証で訂正：作成時は「既定の候補の値に出典未確認を付ける」案を残していた。D21 R5 で既定は使わない：［M-VER］§4〕
5. 事実の欠けと「ない」を分ける：事実が記録されていない（未入力）なら未確定（決める手段＝事実）、「ない」と記録されていれば確定（要件を満たさない）。

## 6. 様式の欄の対応表の鍵と項目

基準は `round2_yoshiki-mapping-table`（以下 YH1〜YH9）。それより古い案は `impl-prep_output-minimal-layer`（以下 OUT-H1〜H12）と、各トピックの出力の節。

### 6.1 置き場所（案）

- 対応表は、ライブラリの中の**判定コアとは別の部品**（SCOPE §3 の「様式の欄の対応表」、§6 の規則1：判定コアは様式を知らず、対応表は計算をしない）。
- 年分ごとのデータ（YAML か JSON）。国の様式なので注入データはない。例外は「寄附先が条例で指定されているか」で、これは住民税の注入データから受け取る（YH6）。
