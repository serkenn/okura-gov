# 複数の市町村に住む家庭で1年分を通したときに見つかった判定コアの問題

- 作成日：2026-11-13
- 作業の群（title1）：`family-run`
- 種類：実測（measurements）。家庭の値（金額・住所・保険者など）はこの文書にもリポジトリにも書かない（AGENTS.md「安全のルール」）。
  入力は `.work/private/`（git 管理外）に置いた。ここには、判定コアの振る舞いとして一般化できることだけを書く。

## 1. 通した家庭の形（一般化）

家族が複数（4つ）の市町村に分かれて住民票を置き、被扶養者の判定と、業務に係る雑所得のある人を含む家庭。
2026-11-18：公開にあたり、家庭の構成の記述を、問題の再現に要る条件だけに改めた（AGENTS.md「安全のルール」）。
問い：所得税 令和7年分、住民税 令和8年度、国年 令和8年度、被扶養者の判定日 2026-04-01。業務に係る雑所得のある人の年間の受取額を振った。

## 2. 見つけた問題

| # | 現象 | 原因 | 状態 |
|---|---|---|---|
| B1 | 問いに住民税の年度を入れると、家族の1人の **所得税.合計所得金額**（所得税の値）まで「未確定」になる。分かれ目は4市町村の住民税の注入点（級地・135万円の非課税の判定の時点）で、「候補の組合せが 1296 通りで上限 64 を超える」として評価しない。所得税の年分だけを問えば値が決まる | 段階評価（扶養の割当て）の段が住民税の値（注入点に依存）を読み、段の出力・グループが最後の計算の全部の値の依存として数えられる（`evaluate.py` の値ごとの候補の評価：`_producer_dependencies`）。所得税（幹）の値がほかの制度の注入点に依存したことになる。家族が複数の市町村に住むと注入点の数が掛け算で増え、上限に当たりやすい | **未修正**（判定コアの評価の仕組みの直しが要る）。回避：市町村の注入データを渡す、または所得税と住民税を別の問いにする。→ **2026-11-13 に修正した**（原因は、ここに書いた段の出力ではなく、人をまたぐ値への全部のグループの付け方・つながった人の全部の数え方・作り手の安全側の決め方の3か所だった。直しと確かめ：`docs/measurements/20261113_family-run_b1-value-dependencies.md`） |
| B2 | 注入データ（級地・税率）を渡すと、`evaluate` が例外で止まる：`自治体の資料は注入データの出典にだけ使える: 住民税.均等割の非課税の基準の額` | 境目の説明の基準の根拠（`evaluate.criterion_basis`）が、基準の値の根拠に含まれる注入データの出典の種類（自治体の資料）を、注入データでない根拠（RULE）の種類に使っていた | **修正した**（2026-11-13。注入データにだけ使える種類を除いて選ぶ。ユニットテスト `packages/core/tests/test_criterion_basis.py`） |
| B3 | 業務に係る雑所得のある人の所得税の値が、前々年分の業務に係る雑所得の収入金額（`prior_income_fixed`）を入れても「未確定」のまま（決める手段：事実）。中間表現の検査を通る記録では消えない | 判定コアの `rules/income_kinds/prior_years.py` が `income_source` の値を `misc_business` で探していた。語彙（`okura_ir.vocabulary` の `prior_income_fixed`、`packages/records/README.md` の表）の値は `miscellaneous_business` で、語彙に合う記録は読まれない。ユニットテストは語彙を通さない辞書で `misc_business` を使っていたので通っていた | **修正した**（2026-11-13。読む値を `miscellaneous_business` に直し、読む値が語彙の列挙にあることを確かめるユニットテストを足した：`packages/core/tests/rules/income_kinds/test_prior_and_rental_choices.py` の `test_source_value_is_in_the_vocabulary`） |

B3 は 2026-11-13 の2回目の通し（実際の値を聞いたあと、令和8年分を問いに入れたとき）に見つけた。同じ種類の食い違い（判定コアが読む列挙の値が語彙にない）がほかの箇所にもあるかは、まだ機械的に確かめていない。

B1・B2 はどちらも、ユニットテストと例の家庭（1〜2市町村・注入データなし）では表に出なかった。複数の市町村と注入データを組み合わせて初めて出た。

## 3. 再現

`.work/private/family/`（git 管理外）の `gen.py`（仮置きの値で中間表現を作る）・`sweep.py`（受取額を振って評価）・`inj.json`（仮置きの注入データ）。
家庭の値を含むため scripts/ には置かない。B2 の再現はユニットテストで足りる。B1 は、4つの市町村に住民票を置く家族で問いに住民税の年度を入れれば、架空の家庭でも再現する。
